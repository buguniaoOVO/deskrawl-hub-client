# 桌破多开中控助手

发布包只有一个 Windows x64 客户端 EXE。客户端窗口、交互代码、文案、配色和图标由本项目重新实现；原有控制引擎压缩后随客户端发布，用来保持助手接口兼容。

客户端首次启动时把运行引擎和桌面 `config.json` 放入 `%LOCALAPPDATA%\DeskrawlHubClient`。之后的设置保存在该目录。客户端从自身内置资源启动本地引擎，控制和界面都通过本机回环地址通信。

本项目只提供桌面控制台，不包含 X1X 游戏助手本体或沙盒插件；包内运行模块只负责控制台本地服务。使用前请另行安装并运行 [X1X 助手](https://x1x.tw/deskrawl/helper/)，中控才能连接和管理助手实例。

客户端使用系统 Microsoft Edge WebView2 Runtime。运行日志保存在 `%LOCALAPPDATA%\DeskrawlHubClient\client.log`。

客户端采用白色工作区、蓝色导航和角色图标。页面提供账号状态、掉落记录、助手设置与运行设置。点击窗口关闭按钮时，客户端会最小化到任务栏并继续运行；点击界面右上角的退出按钮会关闭客户端和内置引擎。

## 主机与沙箱启动

账号状态卡片从助手血脉接口读取角色的血脉评定、百分位和有效样本；无角色数据时显示等待状态。

账号卡片按主机与 Sandboxie 沙箱分别显示，助手离线时仍保留游戏及助手的启动入口。首次使用时，打开各卡片的「环境设置」，确认 X1X 助手目录及游戏路径。游戏可通过该环境的 Steam 启动，也可选择直接运行 Deskrawl.exe。中控只向所选环境提交启动请求。

「助手设置」打开内嵌的 X1X 官网页面，主机与各沙箱使用独立的网页存储。页面打开前，中控读取该助手的配对信息，核对控制端口监听进程及助手返回的沙箱身份。「浏览器打开」会携带当前助手的配对信息；浏览器访问本机网络的权限仍由浏览器管理。

沙箱内的助手会把文件写到该沙箱的映射目录。中控从运行中的助手进程读取其实际路径，再核对配对码和沙箱身份；沙箱 2 的目录显示为 `C:\Users\<用户>\Downloads\...` 时，实际读取位置是 `C:\Sandbox\<用户>\2\user\current\Downloads\...`。内嵌页面只允许当前环境的两条本机端口，并转发页面对助手设置、状态和美术资源的请求。

各环境的目录和启动方式保存在 LocalAppData 下的 DeskrawlHubClient/account-workspace.json。助手更新后，中控在原目录的同级目录查找配对信息一致的新版本。存在多个副本或配对信息时，通过「环境设置」选择。游戏、助手的启动操作分别提交，启动游戏不会自动开启助手的全自动流程。

## 一键部署助手

环境卡的部署入口分两步：先「检测端口」确认这个环境该用哪个控制端口，再「部署助手」把助手装进主机或指定沙盘并启动。部署本身不需要用户先准备好助手安装包。

**检测端口**读取本机监听端口表，用进程路径、沙盘归属、`/control/status` 探测和配对文件四项证据列出候选端口，并给出一个建议端口（优先「探测通过 + 找到配对令牌」的那个）。候选里会写清每个端口凭什么被认成助手，例如 `监听端口 8766（PID 12345）`、`属于沙盘 2`、`已找到配对令牌`。识别不对时可以在部署请求里手动指定端口，手动端口优先探测。

助手没有免令牌的身份接口，所以证据是分层的：无令牌探测出现 401 / 421 只能说明「这是个助手」，不能确定归属；归属必须靠配对令牌 + 带令牌的 200 且助手回报的 `instance.sandbox` 与 `instance.dir` 对得上。**探测没通过的候选也会照样列出来**（界面上标为未确认），不会为了好看把它们过滤掉——目录还找不到的助手往往就靠这些线索找回来。

**部署助手**按下面 9 步执行，界面逐条更新状态，失败会停在出错那一步：

| 步骤 | 做什么 |
| --- | --- |
| 检查运行环境 | 确认沙盘存在、这个环境的助手没在运行、手动指定的端口没被占用 |
| 准备助手安装包 | 用本地包/目录（`packagePath`），或读取官方更新清单拿到最新版本的地址、大小与 SHA-256 |
| 下载助手安装包 | https 下载到 `%LOCALAPPDATA%\DeskrawlHubClient\helpers\packages`，边下载边核对大小与 SHA-256；已缓存且哈希一致时直接复用 |
| 解包并检查内容 | 官方包是加密 zip（口令内置），用系统 `tar.exe` 解开；解包前逐条校验条目路径，拒绝绝对路径、`..` 和别的一级目录 |
| 落位助手目录 | 落到 `%LOCALAPPDATA%\DeskrawlHubClient\helpers\<主机或沙盘名>\X1X-Deskrawl-Helper-<版本>`；同版本已存在就复用，不覆盖正在运行的助手 |
| 准备配对信息 | 沿用包内 `core\helper\runtime\token`，没有就生成一个 64 位十六进制令牌 |
| 启动助手 | 先挑一组空闲端口对，再通过 Sandboxie 在目标环境里启动 `runtime\pythonw.exe core\app\deskrawl_helper.py --open none --port <control>` |
| 等待控制端口 | 最多 60 秒（每 0.5 秒一次），按「本次分配的端口 → `ports.json` → 助手进程的监听端口」顺序探测 `/control/status`，并通过 `instance.sandbox` / `instance.dir` 确认没连到别的环境 |
| 写回账号档案 | 把助手目录写回 `account-workspace.json`，下次打开客户端直接就能连上 |

失败原因按步骤归类，界面会直接显示卡在哪一步：

- **检查运行环境**：没装 Sandboxie（找不到 `SbieDll.dll` / `Start.exe`）；沙盘不存在；「已有实例占用」（这个环境的助手正在运行，或指定端口上已经有助手在监听）；指定的端口对已被占用或被 Windows 保留。
- **准备助手安装包**：连不到更新服务器/超时；更新信息格式或产品名不对；下载地址不在 X1X 的下载空间；本地路径不存在，或目录里缺少 `core\app\deskrawl_helper.py`、`runtime\pythonw.exe`。
- **下载助手安装包**：HTTP 错误、跳转异常、大小或 SHA-256 与清单不符（文件会被删掉）、网络超时。
- **解包并检查内容**：系统没有 `tar.exe`（需要 Windows 10 1803 以上）、条目路径越界、内容不完整。
- **落位助手目录**：目标目录写不进去，或落位后的目录不完整。
- **准备配对信息**：令牌文件写不进去。
- **启动助手**：Sandboxie 拒绝启动，或落位后的助手缺少 `pythonw.exe` / `deskrawl_helper.py`。
- **等待控制端口**：60 秒内助手没有响应控制接口，提示里会列出探测过的端口，并建议手动指定端口；如果端口上的助手属于别的环境，会直接报「连到了别的助手：助手报告的沙箱是「X」，不是本次目标」。
- **写回账号档案**：账号环境尚未就绪。

端口有一条硬限制：助手只认 `(8766+10i, 8765+10i)` 这 12 组端口对（i = 0..11），x1x.tw 面板的 CSP 也只放行 8766–8876，所以部署时会从这 12 组里挑「control 与 api 都没人监听且真的能 bind」的一组；12 组全被占用（含被 Hyper-V / WSL / Docker 保留）时报「端口被占用」，并提示用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看。手动指定的端口优先，超出 8766–8876 时会在步骤说明里提示网页控制台可能连不上。

安全与取舍：下载只走 https，且只接受 X1X 的 r2.dev 下载空间（清单里同时钉死安装包大小与 SHA-256）；解包有路径穿越防护；不覆盖正在运行的助手；同版本目录直接复用。**已知限制：客户端不校验更新清单的 Ed25519 签名**（助手本体自己会验），清单的可信度依赖 TLS、固定下载域名与清单中的大小/哈希。助手安装包本体由 X1X 发布，本项目只负责下载与部署。

## 按账号锁帧

运行设置里的 10/30 帧挡位是全局挡位；账号状态页的每张卡片还可以单独开关锁帧并各自选挡位，多个账号可以同时锁，互不影响。

- 单账号设置按账号 id（`host`、`box:<沙盘名>`）保存在 `%LOCALAPPDATA%\DeskrawlHubClient\frame-cap-settings.json` 的 `accounts` 表里，重启客户端、升级版本后仍然有效。
- 没有单独设置过的账号沿用全局开关与全局挡位，行为和以前一致。
- **全局开关是一键总控**：打开「全局锁帧」会清空所有账号的单独设置，把所有环境统一设成当前挡位；关闭则会清空所有单独设置并让全部环境都不锁帧。想给某个账号开小灶，再单独打开那张卡片即可。
- 账号归属这样判定：先用助手的控制端口把「端口 → 账号」对上，再用游戏 PID 复核；两边都对不上时这个端口只按全局设置处理，绝不会套用别的账号的锁帧设置。
- 每个游戏进程按它所属账号的有效帧率应用：0 表示不锁。游戏重启、换端口、切换账号都会自动重新应用；游戏进程还载入旧限帧组件时提示「重启游戏后再试」。

## 客户端偏好

客户端版本为 `1.3`。版本号只在左下角「中控版本」露出一次，页脚署名不再重复。更新检测使用内置仓库 `https://github.com/buguniaoOVO/deskrawl-hub-client`：启动时和每 12 小时读取一次最新 Release，可按版本关闭提醒，界面上不再需要填写仓库地址。`client-settings.json` 里的仓库地址为空或无效时同样回落到内置地址，只有确实要检测别的仓库时才需要手动改这个文件。检测偏好保存在 `%LOCALAPPDATA%\DeskrawlHubClient\client-settings.json`。

账号状态页提供全局锁帧开关和全部游戏窗口显隐按钮。帧率挡位在运行设置中选择 10 或 30 帧，保存在 `%LOCALAPPDATA%\DeskrawlHubClient\frame-cap-settings.json`。中控从账号状态接口读取当前游戏 PID，将设置应用到所有已识别的 Deskrawl 进程，并在新进程启动后自动应用。关闭锁帧时，组件恢复捕获到的游戏帧率；若游戏没有公开原垂直同步值，则恢复 Unity 默认值 1。

Sandboxie 会将游戏写出的状态文件放入对应沙盒的虚拟文件目录。中控会读取这些目录中的状态文件，以显示锁帧是否已应用。限帧组件只设置 Unity 的目标帧率和垂直同步，不会压缩进程内存或工作集。

即时组件只加载到文件名为 `Deskrawl.exe` 且包含 Unity 游戏模块的进程，通过 Unity 窗口线程应用设置。它不创建监听端口、不扫描或修改其他游戏进程的端口，也不改写 Doorstop 或 X1X 文件。进程访问被 Windows 拒绝时，中控会显示当前游戏未能即时应用的状态。

掉落记录按 X1X 简中装备图鉴校准装备名称与稀有度，每天刷新一次 Wiki 缓存；断网时继续使用本地助手上报的名称。

## 发布与安装

在 Windows x64 上运行：

```powershell
& .\publish.ps1
& .\install.ps1
```

发布文件位于 `publish\桌破中控.exe`。安装脚本会在 LocalAppData 备份原桌面主程序，把新客户端放到桌面为 `桌破中控.exe`，并隐藏旧服务端、旧客户端及旧 WebView2 缓存目录。

发布脚本默认只生成 exe。若要覆盖本机安装版本，在仓库根目录创建 Git 忽略的 `install-path.local.txt`，填写目标 exe 的完整绝对路径；该本地路径不会上传到 GitHub。

## 工程文件

- `MainForm.cs`：单文件宿主、内置引擎提取、隐藏启动与 WebView2 资源路由；锁帧与部署消息的分发。
- `DeployManager.cs`：端口识别与一键部署助手（下载、校验、解包、落位、配对、启动、等端口）。
- `FrameCapLiveManager.cs`：全局与按账号锁帧设置、按端口应用与状态缓存。
- `AccountWorkspace.cs`、`SandboxRuntime.cs`：账号环境配置、沙箱归属校验及独立启动。
- `HelperPane.cs`：各环境独立的内嵌助手页面和本机请求转发。
- `WebAssets\index.html`、`client.css`、`client.js`：全新页面结构、画面和交互。
- `FrameCapLivePlugin\`：原生游戏进程限帧组件源码，发布脚本会先构建并嵌入客户端。
- `Assets\engine.payload.gz`：随客户端封装的兼容运行模块。
- `generate-icon.py`：生成客户端 Windows 图标。
